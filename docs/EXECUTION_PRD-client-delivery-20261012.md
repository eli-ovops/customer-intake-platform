## 3. 来源与版本：何时有效、何时必须重基
最少三表：workspaces保存各段当前JSON及revision/指针；snapshots保存来源、范围、报价、清单/变更的不可变整段JSON；actions保存动作键、payload hash、结果及服务端actor/time。新库事务与外键/唯一约束约束内部关系，不假设两库间有自动外键。原intakes.stage不代表范围或验收状态。

来源维护source v1/v2快照列表和当前指针，含intakeId、submissionId、原version、必要回答副本、规范化UTF-8 JSON的SHA-256，不复制凭据。客户新增提交只显示“有新原文”，不切指针。Eli明确切源才建source v2；v1及旧范围保留。取源时服务端核旧提交id与内容hash，缺失/不一致保留历史只读并标缺口，不按名称重绑；来源未核不能生成当前有效对客材料。

范围冻结锁已提交workspace revision和source revision，生成S1；修改冻结内容只能建S2。报价与清单均保存sourceRevision、scopeRevision、payloadHash。源指针或范围变化后旧版变历史/需核对，不显示当前有效价格或统一“已验收”。恢复aligned的唯一方法是：核对新源、冻结新范围，再显式保存绑定它的新报价和新清单；沿用价格也须形成新版本。清单结果绑定itemId、source/scope/plan revision和受测版本；首版重建清单全部未测，同id改动作、删后再加都不继承旧通过。

变更带baseScopeRevision和预期workspace revision。基线已变则409，不直接采纳：保留提案与所有dirty段，获取现版供对照，Eli改成对新基线的提案，再用新requestKey提交；不自动合并。采纳、新基线、指针与动作回执同一新库事务。唯一键作用域为(workspaceId,action,requestKey)，存规范payload hash；同键同载荷返回原结果，同键异载荷拒绝。字段拒绝/409不产生业务版本；结果不明先鉴权查询原键，再决定同键重试，不换键重复采纳。

## 4. CNY报价的固定规则
销售栏是Eli输入的固定价草案，内部估算不是销售公式。第三方固定成本单列金额与“Eli承担/客户直付/待定”；不自动加到销售总价。责任或金额未知保持待定。每阶段销售价、第三方成本、计算后估算均为整数分0—100,000,000，各类总额≤1,000,000,000分；可选估算分钟0—60,000，费率0—1,000,000分/小时，最多10阶段。非整数、负数、金额超过两位小数或算后越界拒绝，不截断；中间乘积≤60,000,000,000，安全整数内。

估算按阶段 floor((分钟×费率分+30)/60) 四舍五入到1分，先舍入各阶段再累加；固定销售金额直接累加。销售任一包含阶段未填，显示“总报价待估；已填写部分小计”，不能当0。内部估算缺值只影响内部估算，不把已填销售价抹掉。显式0须备注；成本“不适用”须显式选择，不能由空值推定。

| 黄金用例 | 精确预期 |
|---|---|
| G1：90分钟×10,000分/小时；销售填12,000分；Eli成本2,000分 | 内部估算15,000分；销售仍12,000分，不能自动加成本或改成估算价 |
| G2：1分钟×100分/小时 | 内部估算2分，不是1分或1.67分 |
| G3：两个阶段各1分钟×30分/小时 | 每阶段0.5分各舍入1分，总2分；不能先合并舍成1分 |

## 5. 保存、根身份与必要安全
复用旧auth/CSRF、会话过期/首次改密、Host/Origin、纯文本显示。新敏感GET、写、下载均鉴权并核intake/workspace归属；客户回访Bearer不读内部交付。身份由服务端写，拒绝伪actor与越权路径。所有开发、验收先用独立合成intake库与delivery库，真实旧库不读写。

每次只提交一段的有界块或单动作，客户端包≤40KiB，服务端保留48KiB，不能整页或全历史单请求。每工作台最多50条问题/范围、10报价阶段、50变更、100验收；单文本≤1000字。401/409/413/写失败留住四段所有dirty内容，提供浏览器下载或复制“未提交编辑文本”，不依赖服务端落盘；重新认证/读取新revision后核对另存，不能自动覆盖。未保存内容不承诺浏览器关闭后的零丢失。

初始化、正常启动、隔离恢复分模式；正常打开前核实际数据根登记的rootId/producer/schema及介质状态，不按机器名绑定。已初始化标记下缺/坏库、未来schema、失去挂载或身份不符停止受影响写入，不调用旧初始化逻辑补空库；旧问卷不因delivery不可用被重建。第二实例对同根拿不到独占写身份则拒绝写，换端口也不解除；残留锁核所属PID/根，未知不强删。丢外盘不能声称同盘备份仍可读。

合成交付根容量：两库及WAL/SHM/认证元数据合计64MiB，其中历史32MiB，控制元数据预留1MiB；备份128MiB；导出和在途包合计64MiB，总256MiB。逐类预检、到限拒绝新增，保留既有数据、许可撤销与dirty文本挽救；撤销无法持久化时阻断对客包。不自动清理或无界扩容。故障通过专属适配器注入，不拔真实盘或改真实权限。

## 6. 三种资料文件与双库恢复
一次导出锁定已提交workspace revision、全部source/scope/quote/plan引用及对客核准；dirty未保存须先保存或只下载未提交文本。每次新exportId，在专属未完成目录写完文件、字节hash/清单并回读后才COMPLETED和显示下载；第二/末文件失败标FAILED/PARTIAL、旧包不变、保留现场；查同exportId核结果，不能重读新数据拼旧包。

内部JSON保留该工作台全部资料/历史；内部Markdown包含内部估算、成本与待问备注。对客沟通Markdown由独立白名单构造：经核准的目标、范围交付物/排除项、待确认问题、CNY销售草案、验收动作与适用前提；始终标“待确认/草案”。不包含成本、费率、内部备注、原始回答全文、敏感路径或秘密。Eli预览并核准精确文本及依赖版本；修改文本/依赖/许可使核准失效。未知许可只允许内部资料；生成文件不等于发送。合成夹具用明确虚构许可验证分流，不要求真人批准测试。

对客核准绑定textHash、许可修订及source/scope/quote/plan依赖。对客包转COMPLETED前、每次新对客下载前，服务端核当前许可/核准仍有效，textHash与锁定文本相符、依赖版本仍对齐；只核元数据，不重新读取正文混包。锁定后撤销或失效，中止对客完成/下载并保留内部现场；已完成后撤销保留历史完成回执，但拒绝新对客下载，不能凭旧许可输出。合法内部资料仍走独立鉴权通道。

manifest至少有producerApp、appVersion、schemaName/schemaVersion、exportId、createdAt（带时区）、sourceRevisionRefs、files(relativePath/sha256/bytes)、verificationCoverage、limitations、privacyMode、status；路径仅包内相对路径，拒绝穿越。JSON资料包不是SQLite完整备份，不含凭据、会话或其他客户；不承诺三工具互导/同步。

双库备份由服务级停写屏障覆盖原问卷提交/草稿、备注/阶段、auth/审计及delivery全部写入口；拒绝新写、排空在途写入，屏障期间用SQLite backup分别取两库，写同batch manifest并逐条核intake/submission/source hash和版本引用。任一步失败整批不可恢复/不可标COMPLETED；安全解除屏障或明确只读，不能留下静默锁死，不能只检查integrity_check。

恢复只接受完整批次，在新数据根、新端口及独立AUTH_ROOT/运行认证域中启动副本；备份账户/会话仅历史，不复活旧cookie或客户能力，原账户不改。核两库schema、完整性、hash和每条引用；缺源或sha不符记录历史只读，恢复校验未全过不得COMPLETED。恢复不覆盖日常库、不自动切换；备份敏感认证内容不进入普通资料包。首次全用合成库完成，真实备份/切换另需明确对象授权。
